% Installation and the public mental model.
\section{Install and read the language}\label{ch:install}

The complete installation is two lines:

\begin{Verbatim}[fontsize=\small,frame=leftline]
\usepackage{tenkz}
\begin{tenkz}[physical=up] \tn{A} & \tn{B} \end{tenkz}
\end{Verbatim}

For a repository checkout, put \tnfile{tex/tenkz/} on
\texttt{TEXINPUTS}; for an archived article, ship \tnfile{tenkz.sty} and
its package files beside the source.  XeLaTeX is the reference engine for
print and for the XDV-to-SVG web route.

The language contract is one sentence:

\begin{quote}\large
A picture chooses one layout; its options declare topology and policy; its
body declares atoms, connections, regions, and annotations.
\end{quote}

Read a source in that order.  The environment chooses the placement grammar.
Its optional argument states facts shared by the picture.  Body commands
declare records; they do not perform an imperative drawing procedure.

Five classes cover the public vocabulary: \emph{atoms}; \emph{connections
and closures}; \emph{regions and annotations}; \emph{composition}; and
\emph{setup and extension}.  A command declares an object in one of those
classes.  A key modifies the record being declared.  This distinction keeps
the grammar small enough to read from source.

Scope is explicit.  \tncmd{tnset} is document scope; an environment option is
picture scope; an atom option is object scope; and a join or side-policy
option is connection scope.  A shared key name has one value type and one
meaning in every environment that exposes it.

Open ink is mathematical data.  A matrix keeps its two virtual indices; a
map keeps input and output indices; a scalar has none.  Closing a picture for
neatness changes the object.  The versioned \tnfile{.tnlog} records the
resolved model and boundary signature used for rendering.  It also records
every port's type, which the page does not: a contracted index carries its
type in the record and not in its line, so a physical contraction and a
virtual one stroke alike.
